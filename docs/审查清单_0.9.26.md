## 二、待办（按优先级，均未动代码）

### P1-A `source` 是裸字符串，拼错不报错

- 位置：`HextechRegistry.java:266-272`（`isSourceEnabled`）
- 现象：`source` 写错一个字母（如 `irons_spellbook`），`ModList.isLoaded` 判定永远 false，那些海克斯永远抽不到；无编译错误、无运行日志。
- 影响面：370 个联动海克斯 + 141 个 DLC 海克斯。
- 改法：启动期遍历全部 `HextechDefinition.source`，把非空且非 `vanilla`/`dlc_*` 的值收集起来，逐个对照 `ModList.get().getMods()` 里已知的 modId；不认识的打一条 WARN 并列出 id。
- 成本：一个循环 + 一行日志，不动玩法。
- 价值：挡住「某个联动悄悄消失」这类最难排查的问题。
- **状态：已实现（0.9.26 工作区）**
  - `HextechRegistry` 新增 `validateSources()`，遍历 `DEFINITIONS` + `EQUIPMENTS` 的全部 `source`，复用第 92 行已有的 `KNOWN_SOURCES` 白名单（15 联动 + 3 内置 DLC）比对，不在名单的打 WARN 并统计条数。
  - 调用点两处：`HexDataLoader.apply` 末尾、`EquipmentDataLoader.apply` 末尾（两个 loader 执行顺序不确定，各挂一次；幂等，最多多一行日志）。
  - 关键取舍：**白名单内的 mod 即使玩家没装也不报**——那是正常状态，由 `isSourceEnabled` 静默过滤；只有「不在白名单」才可能是拼错。
  - 静态验证：528 条带 `source` 的数据、18 种来源，**0 个不在白名单**，首次启动不会产生误报。
  - 编译：`compileJava` BUILD SUCCESSFUL，仅剩原有 6 条 deprecation 警告。
  - 未做：没有真机启动看实际日志（需要进游戏或起服务端才能看到那行 INFO）。

### P1-B `CLASS_REQUIRE_MOD` 手写 Map

- 位置：`HextechRegistry.java:392-405`
- 现象：12 条 `Map.entry("hex_class_xxx", "modid")` 硬编码。
- **实测修正**：原判断「12 条易漏」不准确。实际有 **16 个 `hex_class_*`**，构成是「12 个依赖外部 mod + 4 个纯原版机制」，目前**完全对齐，没有漏登记**：

  | 类型 | 成员 | 是否进 Map |
  |---|---|---|
  | 依赖外部 mod | cook / blade / arcanist / slayer / shaman / curator / relic / dragonknight / beastmaster / alchemist / gunsmith / woodwalker | 是（12） |
  | 纯原版机制 | archaeologist（刷子）/ beekeeper（蜜蜂）/ trimmer（盔甲纹饰）/ warden（信标） | 否（刻意） |

- 真正的风险只剩「以后新增职业包时漏登记」，所以做的是**防未来校验**，不是修 bug。
- **状态：已实现（0.9.26 工作区）**
  - 新增 `VANILLA_CLASSES` 常量，显式列出 4 个原版职业（`HextechRegistry:407-411`）。
  - `validateSources()` 内增加职业包检查：`hex_class_*` 若既不在 `CLASS_REQUIRE_MOD` 也不在 `VANILLA_CLASSES`，打 WARN 列出 id。
  - 覆盖率静态验证：12 + 4 = 16 = 定义数，两集合无重复、无遗漏、无多余文件，**启动时不会误报**。
  - 编译：BUILD SUCCESSFUL。

### P1-C `mods` 字段名有歧义

- 位置：835 个 JSON 的顶层字段 `mods`
- 现象：内容是 `[{"attr": "max_health", "perLevel": 4.0}]`，即**属性修饰列表**，与「模组」无关。774 个 hextech 全用它。
- 影响：接手者第一次读数据会误判成「依赖哪些 mod」；实际依赖信息在 `source` 字段。
- 改法：不改字段名（改名要动 835 个文件 + 加载器 + 全部脚本，风险远大于收益）。只在 `22-内容管线与数据驱动.md` 补一句说明：`mods` = attribute modifiers，`source` = 归属/依赖标记。
- **状态：已实现（2026-11-14）**
  - `22-内容管线与数据驱动.md` 第三节开头新增「两个最容易看错的字段名」对照表，写清 `mods` 是属性修饰列表（`attr` + `perLevel`）、`source` 才是依赖标记，并点出 `isSourceEnabled:272` 的 `isLoaded` 判定才是「没装就不进池」的执行点。
  - 同时写明「不改名」的理由，避免以后有人反复提议改名。
