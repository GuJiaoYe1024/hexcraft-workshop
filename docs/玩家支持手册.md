# 玩家支持手册

对应规范：12-手感与反馈设计、27-玩家反馈与 bug 处理、33-包体与首次启动体验、39-玩家社区沟通与公告。

---

## 1. 反馈通道现状（12 号）

规范说一次满足的命中要有 5~8 个小反馈在 100ms 内同时触发。本项目的实际状态：

| 通道 | 现状 | 说明 |
|---|---|---|
| 音效 | **不做** | 用户 2026-11-14 拍板不做音效。全项目 `playSound` 命中 0 处 |
| 粒子 | **不做** | 同类拍板。`addParticle` / `sendParticles` 命中 0 处 |
| HUD 数字跳字 | 有 | 抽取、锻造、入账走滚动提示 |
| 面板动效 | 有 | 界面开合、`effectBatch` 批量刷新 |
| tooltip | 有 | 自绘 tooltip（`HexFonts.tooltip`），原版 `renderComponentTooltip` 文字强制带阴影关不掉 |
| 屏幕抖动 | **不可行** | MC 事件层做不到，需要 mixin 或相机钩子 |
| 顿帧 | **不可行** | MC 没有 timeScale 概念，冻结世界会停掉服务端 tick |

**为什么不补齐音效和粒子**：这是用户明确决定，不是遗漏。但要知道代价——按 12 号的结论，声音承担约一半的感知质量，缺了它「打击感」会明显偏弱。如果以后想改，12 号列的可做项是：`level.playSound` 按重要度分档、`sendParticles` 一次爆发 8~20 个，并且高频事件（叠层、命中）必须节流，不能每 tick 都播。

**当前不要做的事**：不要把「屏幕抖动 / 顿帧」写进需求列表——检测口径已经确认本项目做不到，写进去只会变成永远完不成的待办。

## 3. 玩家报告收集表（模板）

单人开发够用的最小结构。收到报告时先把这几列填上，填不出来的就是你要问的。

| 列 | 填什么 |
|---|---|
| 编号 | R1、R2…顺序编号，不要复用 |
| 来源 | CurseForge 评论 / QQ 群 / GitHub Issue / 私信 |
| 描述 | 玩家原话，不要自己改写 |
| 分类 | Crash / Gameplay / Visual / Cosmetic 四选一 |
| 严重度 | Critical（不能玩）/ Major（能玩但受损）/ Minor（注意不到） |
| 能否复现 | 必现 / 偶现 / 无法复现 / 未验证 |
| 版本 | 玩家报的 mod 版本号 |
| 处置 | 修 / 重复 / 不是 bug / 需要信息 |
| 关联版本 | 修在哪个版本 |

**每条报告先问三句**（顺序别换）：

1. **只装本 mod 能复现吗？** —— 排除联动冲突，这是最常见的误报来源
2. **有日志吗？** —— `logs/latest.log`，没有日志的崩溃基本查不动
3. **什么版本？** —— 0.9.x 迭代很快，很多「bug」是旧版已修的

**分类要快**：在两个级别之间犹豫超过 30 秒，就选高的那个。高估一档只是效率损失，把 Critical 低估会让玩家一直受苦。

## 4. 回复模板（39 号）

模板的作用是**不冷场、不敷衍、给出下一步**。四条原则：先确认收到了、再说事实、明确下一步、不承诺时间。

### 4.1 收到崩溃报告

> 收到，这个是崩溃问题，优先级最高。
> 需要你补三样我才能定位：`logs/latest.log` 里崩溃那一段、当时的 mod 版本、以及只装本 mod（不装其它联动 mod）能不能复现。
> 有了这三样我基本能确定是不是我的问题。

### 4.2 收到玩法异常

> 收到。想确认一下：这个现象是**偶发**还是**每次都这样**？
> 如果是每次都能复现，麻烦说一下具体操作顺序（点了什么、在第几级、有没有装联动 mod）。
> 我这边先按你描述的路径自己跑一遍。

### 4.3 判定「不是 bug」

> 查了一下，这个是**设计如此**，不是 bug：[说清机制]。
> 如果你觉得这个设计不合理，也告诉我——数值和规则都可以调，但我要先知道你的实际体验，不然改了也不知道往哪调。

### 4.4 判定「重复」

> 这个和之前 R[N] 报的是同一个问题，已经记在待办里了，我把它合并过去。
> 那边有进展我会在这个帖子里回。

### 4.5 判定「需要更多信息」

> 目前的信息还不够定位。能不能再补一下：你的游戏版本、Forge 版本、完整 mod 列表、以及 `latest.log`？
> 没有这些我只能猜，猜出来的修法往往改错地方。

### 4.6 已修复通告

> 已在 v0.9.x 修复：[一句话说清改了什么]。
> 如果更新后还有同样现象，直接在这个帖子回我，说明是新问题还是老问题。

**不要做的事**（27 号明确要求）：未经确认就关闭或标「不修」；把报告直接塞进已有计划里不说；用「趋势数据」当停工依据。

## 5. 安装自查 5 步（33 号）

给玩家的自助排错，按顺序做，做完还不行再报。

**第 1 步：版本对得上吗**

- Minecraft 必须是 **1.20.1**
- Forge 必须是 **47.x**（`mods.toml` 里写的是 `[47,)`，低于 47 直接不加载）
- mod 文件名形如 `hexworkshop-1.20.1-0.9.x.jar`，放在 `.minecraft/mods/` 下

**第 2 步：是不是只装本 mod 也出问题**

把 `mods/` 里除本 mod 和 Forge 之外的都临时移走，再启动一次。

- 只装本 mod正常 → 是联动冲突，把移走的 mod 一半一半加回来，定位到具体那个
- 只装本 mod也出问题 → 继续第 3 步

**第 3 步：看日志里有没有 ERROR**

打开 `logs/latest.log`，搜这几个关键词：

| 搜什么 | 说明什么 |
|---|---|
| `Hexcraft` + `ERROR` | 本 mod 自己的报错 |
| `loaded N hextech definition(s)` | `N` 后面的失败数应该是 0，不是 0 说明有 JSON 坏了 |
| `Missing or unsupported mandatory dependencies` | Forge 版本不够 |
| `java.lang.NoClassDefFoundError` | 少前置库，或版本不匹配 |

**第 4 步：配置文件是不是旧的**

配置文件在 `config/hexworkshop-common.toml` 和 `hexworkshop-client.toml`。

从很旧的版本升级上来时，如果界面里某些选项显示成原始键名（像 `hexcraft.config.xxx`），说明**语言文件没加载**，不是配置坏了——重开客户端或按 F3+T 重载资源。

**第 5 步：还不行就报，带上四样东西**

1. mod 版本号
2. Forge 版本 + Minecraft 版本
3. 完整 mod 列表（`mods/` 文件夹截图即可）
4. `logs/latest.log`

四样齐全的报告，定位速度比只写「打不开」快一个数量级。

## 6. 一句话总纲

玩家报的问题里，**大部分不是 bug，是环境**。所以流程的顺序永远是：先确认环境 → 再确认能不能复现 → 最后才怀疑代码。反过来做，会在错误的方向上改很久。
