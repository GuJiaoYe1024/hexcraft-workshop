# 40 份规范 × mod 现状对照（v0.9.28）

> 做法：逐份读规范，只提取「能验证的要求」（方法论、背景介绍不算），再拿每条去核代码/数据/文档。
> 三态：`已达` / `部分达` / `未做`。
> 本文只读不改。核对顺序按规范编号。

## A. 规范要求清单（按篇号提取）

### 01 介绍写法规范

| # | 要求 | 来源 |
|---|---|---|
| 01-1 | desc 四要素齐全：触发 → 目标 → 效果 → 数值 → 上限/持续 | 二、三 |
| 01-2 | desc 每个数值都能在 JSON 找到同键 token，禁止写机制不存在的字段 | 六-1 |
| 01-3 | 禁止「提升 / 增强 / 更强」这类无数值词 | 六-3 |
| 01-4 | 禁止「联动 XX」尾巴 | 六-4 |
| 01-5 | 禁止「穿上才生效」「生效规则」这类常识 | 六-5 |
| 01-6 | 禁止一条里出现两套数值口径（既写每层又写总计） | 六-6 |

| 01-8 | 禁止给「层在产物上」的件写「命中层 / 受击层」 | 六-2 |
| 01-9 | 条件与结果同一行，无孤立词 | 六-9 |
| 01-10 | 全角 `（）`【】「」『』 在中英语言文件中必须为 0 | 四 |
| 01-11 | 数字一律阿拉伯数字；概率写 %、层数写「层」、时间写「秒」 | 二-2,8 |
